# Release guide

## Release contract

The release workflow starts only for a pushed, strict semantic-version tag:
`vX.Y.Z`. It runs the same quality checks as CI, builds a ZIP, and requires all
three versions to equal `X.Y.Z`:

- the Git tag without its leading `v`;
- `package.json` `version`;
- `dist/manifest.json` `version` after the build.

The package contract is `gitlab-fast-pipe.zip` in the repository root. If the
project chooses another path, update both workflow environment variables and
this document in the same change.

## Release prerequisite checklist

- [ ] The commit is on the default branch and CI is green.
- [ ] `package.json` and the built `dist/manifest.json` have the intended
      identical `X.Y.Z` version.
- [ ] `npm run check:zip` passes for `gitlab-fast-pipe.zip`.
- [ ] The first Store item, listing, privacy declaration, visibility, and
      service-account access are configured as described below.
- [ ] Repository variables are set.
- [ ] An annotated tag `vX.Y.Z` points at the release commit.

## One-time Chrome Web Store setup

1. Register the publisher in the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole/).
2. Upload the first package manually. Complete its Store listing and Privacy
   tabs, choose visibility, and record the extension ID and publisher ID. API
   V2 cannot create an item. Ready-to-copy listing material is in
   [`store-listing.md`](store-listing.md).
3. In the Google Cloud project, enable **Chrome Web Store API**.
4. Create a dedicated service account for release automation. In the Chrome Web
   Store Developer Dashboard, grant that service account email access to the
   publisher/item.
5. Create a Workload Identity Pool and a GitHub OIDC provider. Restrict the
   provider's attribute condition to this GitHub organization/repository and
   the release workflow or protected release environment.
6. Grant the matching `principalSet` `roles/iam.workloadIdentityUser` on the
   service account. This permits the GitHub identity to impersonate it. No
   service-account key is needed.

The API needs OAuth scope
`https://www.googleapis.com/auth/chromewebstore`. A service account must be
explicitly added in the Store dashboard; IAM access in Google Cloud alone is
not enough.

## GitHub configuration

Create these **repository variables** (not secrets):

| Variable | Value |
| --- | --- |
| `GOOGLE_WORKLOAD_IDENTITY_PROVIDER` | Full provider resource name, for example `projects/123456789/locations/global/workloadIdentityPools/github/providers/repository`. Use the project number. |
| `GOOGLE_SERVICE_ACCOUNT` | Dedicated service-account email. |
| `CHROME_WEB_STORE_PUBLISHER_ID` | Publisher ID from the Chrome Web Store Developer Dashboard. |
| `CHROME_WEB_STORE_EXTENSION_ID` | Existing item ID from the Store dashboard. |

The workflow references a `chrome-web-store` GitHub Environment but does not
require protection rules, so a valid release tag publishes automatically by
default. Teams may add environment reviewers as an optional release-control
measure. The release job has `id-token: write` and fetches a short-lived access
token through OIDC.

## Publish a release

1. Ensure the default branch passes CI and the version is ready in
   `package.json` and the manifest generated by the build.
2. Create and push an annotated `vX.Y.Z` tag that points to that commit.
3. Inspect the workflow's upload and publish responses and the Store dashboard.
   An API publish submits the item for review; availability depends on Chrome
   Web Store review and the item's existing visibility setting.

The workflow calls Chrome Web Store API V2:

- `POST https://chromewebstore.googleapis.com/upload/v2/publishers/{publisherId}/items/{extensionId}:upload`
- `POST https://chromewebstore.googleapis.com/v2/publishers/{publisherId}/items/{extensionId}:publish`

These endpoints and the service-account flow are documented by Google in
[Use the Chrome Web Store API](https://developer.chrome.com/docs/webstore/using-api)
and [the V2 API reference](https://developer.chrome.com/docs/webstore/api).
